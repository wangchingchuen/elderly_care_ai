## 查詢與資料驗證

- 本機 Qwen 實測：進食、跌倒、日誌摘要、英文坐姿查詢，以及「吃了多少」超出能力的問題。
- 明確拒絕用影片推論攝取量、服藥與診斷；關鍵字備援也維持此限制。
- 不同住民、未指定追蹤與被排除的事件不會混入回答。
- 時間篩選涵蓋跨午夜影片的事件起始時間；每週比較附兩期證據，不把片段數當成健康變化。
- 每次覆核保留狀態、備註與時間；服務重啟後完成紀錄仍存在。
- 不安全上傳檔名不會決定磁碟路徑；CSV 欄位避免公式注入。
- 任務失敗後下一個任務仍能執行；中斷任務可重試，分析中的影片不能刪除。

## 本次測試修正的問題

1. 補齊 OmDet 必要的 timm 依賴，修復 meta 載入後未初始化的 Swin 位置索引與遮罩。未改變模型權重。
2. 原本單一腿／軀幹比例會把直立誤判為坐姿，改為同時參考膝關節角度。
3. 進食線索必須持續至少一秒，排除正常躺下片段內短暫的手／物件巧合。
4. 追蹤分段可人工複選，並修正快速連續修改造成舊請求覆蓋的競態。
5. LLM 分類輸出需通過允許清單與明確關鍵字檢查；無效時標示備援，不假裝模型成功。
6. 影片與查詢的首次模型初始化共用鎖，避免背景執行緒同時更動模型建構環境。

## 仍需後續驗證

- 5090 的推論速度、CUDA 實際可用性、訓練與 VRAM 使用量未在這台 CPU 環境測試。
- 正式部署前仍需要跨住民、跨鏡頭、遮擋與不同光線的獨立標註資料。
- 一秒門檻可能漏掉更短的真實進食動作；手／食物線索仍不能證明吞嚥或攝取量。
- 簡單 IoU 追蹤可能分裂、重複偵測或換人，住民歸屬依人工確認；不做跨鏡頭識別。
- LLM 只做有限行為查詢規劃。照護背景目前供人工參考，不會自動推論個人健康基準。
- 本機環境重用已安裝的 CPU PyTorch／Ultralytics 套件；新增依賴安裝在專案 `.venv`。全新 Windows 電腦的完整安裝腳本與 CUDA 分支尚未在另一台機器重建驗證。
